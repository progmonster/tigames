# Модель в шестиугольнике

Принимай фото, размер рамки в мм и способ измерения. Если есть одобренный
рисунок, используй именно его; повторно не генерируй модель.

## Параметры

- `photo`: фото; `approved_lineart`: необязательный одобренный рисунок.
- `size_mm`: положительный размер **внешней** рамки вместе с обводкой.
- `measure`: `across-flats` — между противоположными сторонами;
  `across-vertices` — между противоположными вершинами, большая диагональ.
  Если дан просто размер без способа измерения, уточни его.
- Необязательно: поля A4 (10 мм), отступ в квадратной карточке (3 мм), обводка
  рамки (0,12 мм), зазор до рамки (0,03 мм), DPI PNG (600), книжная/альбомная
  страница и количество карточек на одном листе.

Большая диагональ правильного шестиугольника = размер между сторонами / cos(30°).
Модель пропорционально масштабируется под рамку. Размер не относится к полям PNG.

## Фото → контуры

Перед генерацией прочитай [references/illustration-prompt.md](references/illustration-prompt.md).
Используй доступный инструмент генерации/редактирования изображения, фотографию
как референс и настоящий прозрачный фон. Шестиугольник на этой стадии не рисуй.
Не заменяй создание иллюстрации простым выделением краёв фото: стол и блики
не являются конструктивными линиями.

Сохрани ракурс, пропорции, соединения, отверстия, зубья и внутренние кромки.
Удали фон, фактуру, тени и блики. Не придумывай скрытые детали. Укажи конкретную
неопределённость, если важный участок неразличим. Не требуй одобрения каждой
стадии, если пользователь уже поручил выполнить полный процесс.

При наличии одобренного рисунка пропусти генерацию. Цветные контуры и шахматная
подложка допустимы только во входном файле. Храни исходники без изменений и
фиксируй, какая версия использована для результата.

## Контуры → вектор → печать

Используй [scripts/build.py](scripts/build.py): он принимает **контурный рисунок,
не фотографию**. Из корня проекта после подготовки окружения (`uv sync`):

```bash
.venv/bin/python Skills/photo-to-hexagon/scripts/build.py \
  --lineart path/to/lineart.png \
  --size-mm 34 --measure across-flats \
  --output-dir outputs/model-34mm
```

Для большой диагонали: `--measure across-vertices`. Остальные параметры — `--help`.
Создавай новый каталог; не используй `--overwrite` без необходимости.
CairoSVG требует системную библиотеку Cairo; помощник ищет стандартные пути
Homebrew на macOS. Не устанавливай неизвестные бинарные сборки.

Помощник обеспечивает:

1. PNG: все видимые пиксели RGB 0/0/0, альфа только 0/255. Белые заливки,
   светлая шахматная сетка и цвет удаляются, включая **внутренние** области.
   Порог настраивается; нет удаления мелких компонентов и закрытия отверстий.
2. Настоящую трассировку кривыми. Отверстия — прозрачные составные контуры,
   не белые объекты. Растровые изображения не встраиваются в SVG.
3. Численный поиск почти минимальной правильной рамки по геометрии вектора:
   выпуклая оболочка, перебор угла, оптимизация центра и апофемы, локальное
   уточнение. Не строить рамку вокруг прямоугольника прозрачного холста.
4. Масштаб под выбранный размер внешней рамки с учётом её толщины, вершин
   и технического зазора. Модель целиком внутри внутренней границы рамки.
   Касание всех шести сторон одновременно не требуется.
5. Отдельные SVG-группы `model-outline` и `enclosing-hexagon`, PNG той же
   композиции и PDF A4 с векторными моделями.
6. **Квадратные** карточки обычной сеткой. В каждой — одна модель с рамкой,
   одинаковые отступы; линии разрезания только в PDF. Без сотовой укладки
   и максимального уплотнения. Слишком большой размер — ошибка, не повод
   молча уменьшать рамку.

При изменении геометрии, объяснении размера или диагностике прочитай
[references/geometry-and-print.md](references/geometry-and-print.md).

## Проверка и выдача

Проверь `manifest.json` и контрольные изображения. Увеличь отверстия и зубья:
подложка должна просвечивать через все незакрашенные области. Белая заливка
может оставаться внутри изображения с прозрачным внешним фоном.
Проверяй **именно выдаваемые файлы**, не другую похожую версию.

Отрисуй итоговый PDF доступным рендерером, например:

```bash
pdftoppm -r 150 -png -singlefile outputs/model-34mm/sheet-a4.pdf \
  outputs/model-34mm/work/pdf-check
```

Проверь квадратную сетку, поля, отсутствие обрезанных рамок. Если применяешь
доступный PDF-навык, соблюдай его контракт создания и визуальной проверки.
Экранное сглаживание SVG/PDF нормально; бинарность требуется от итогового PNG.

Не обещай доказанный глобальный минимум: поиск приближённый. Не выдавай
PNG внутри SVG за векторизацию. При недоступном инструменте укажи блокер.

Выдай `model-outline.svg`, `model-outline.png`, `sheet-a4.pdf`. Укажи заданный
размер и способ измерения, сторону квадратной карточки, число карточек на A4.
Печать: **100% / «Фактический размер»**, без «Вписать в страницу».
